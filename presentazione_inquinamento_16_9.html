Fase 1 • Traccia & Obiettivi

Traccia dell'Esercizio: Sistema Inquinamento con Monitor

Estensione dell'architettura Client-Server concorrente con stazioni di notifica emergenze (Monitor).

📡 1. Client Sensore (Centraline)

Rappresenta stazioni di rilevamento distribuite sul territorio:

  • Generazione dato: genera un intero casuale tra 80 e 100 ppm.
  • Connessione breve (Short-lived): apre la connessione TCP solo per inviare il dato (SENSOR:<val>).
  • Chiusura e riposo: riceve l'ACK dal server, chiude la socket e si sospende per 5 secondi prima del ciclo successivo.
  • Esecuzione concorrente: molteplici client operano in parallelo senza conoscersi.
💡 Ogni risveglio genera una nuova connessione socket verso il server.
🖥️ 2. Server Centrale & Concorrenza

Coordina l'aggregazione dei dati e arbitra l'accesso alle risorse condivise:

  • Soglia dinamica: inserita dall'utente all'avvio (tra 80 e 100 ppm).
  • Server concorrente multithread: accetta infinite connessioni e istanzia un thread dedicato per ciascuna.
  • Semaforo di mutua esclusione: protegge l'aggiornamento di somma, numero campioni e calcolo media.
  • Rilevazione allarme: se la media supera la soglia, scatta l'allarme globale.
⚠️ Vincolo Tassativo: vietati attributi static! Stato condiviso gestito a oggetti (OOP).
🚨 3. Client Monitor (Supervisione)

Novità dell'esercizio: postazioni di emergenza (es. Protezione Civile, Sala Operativa):

  • Connessione persistente (Long-lived): si connette all'avvio inviando il comando MONITOR.
  • Iscrizione alla lista: il server registra il canale di output del monitor in un elenco sicuro.
  • Ricezione notifiche push: resta in ascolto passivo; appena la media sfora la soglia, riceve l'allarme istantaneamente dal server.
  • Disconnessione robusta: se un monitor si scollega, il server ne rimuove la connessione senza crash.
🔔 Notifica asincrona: i monitor vengono allertati istantaneamente ad ogni superamento!
Fase 2 • Teoria e Protocollo

Protocollo di Rete e Mutua Esclusione con Semaforo

Come i thread gestiscono l'accesso concorrente e come si differenziano i due tipi di client.

🔒 Il Semaforo e la Race Condition evitata

Quando più sensori inviano dati contemporaneamente, più thread del server cercano di aggiornare le stesse variabili in memoria condivisa:

// In assenza di sincronizzazione (RACE CONDITION!):
Thread A legge: somma = 180, N = 2
Thread B legge: somma = 180, N = 2
Thread A scrive: somma = 270 (180+90), N = 3
Thread B sovrascrive: somma = 275 (180+95), N = 3 ← DATO PERSO!

Soluzione con Semaphore(1, true):

  • 1 Permesso: mutua esclusione stretta (solo un thread per volta nella sezione critica).
  • Fairness true: politica FIFO per evitare la starvation tra thread concorrenti.
  • Blocco finally { semaforo.release(); }: garantisce il rilascio anche in caso di eccezioni a runtime.

🔄 Registrazione Dinamica (Hot-Plugging):

I monitor si iscrivono a caldo nella CopyOnWriteArrayList del Server senza fermare il servizio. Il broadcast degli allarmi avviene fuori dal Semaforo per evitare che monitor lenti blocchino i thread dei sensori periferici.

Fase 4 • Codice Sorgente Java

Implementazione Java: OOP Pulita & Dependency Injection

Esame dettagliato delle classi che compongono la soluzione. Nessun attributo di classe static.

/**
 * Gestisce lo stato condiviso del sistema in modo concorrente.
 * VINCOLO SODDISFATTO: Nessun attributo statico!
 */
public class RegistroInquinamento {

    private int numeroRilevazioni;
    private long sommaRilevazioni;
    private double mediaCorrente;
    private final double sogliaMassima;

    // Semaforo binario FIFO per mutua esclusione
    private final Semaphore semaforo;

    // Lista thread-safe per gestire le connessioni dei monitor registrati
    private final List<PrintWriter> monitorConnessi;

    public RegistroInquinamento(double sogliaMassima) {
        this.sogliaMassima = sogliaMassima;
        this.numeroRilevazioni = 0;
        this.sommaRilevazioni = 0;
        this.mediaCorrente = 0.0;
        this.semaforo = new Semaphore(1, true);
        this.monitorConnessi = new CopyOnWriteArrayList<>();
    }

    public EsitoAggiornamento registraRilevazione(int valore) throws InterruptedException {
        boolean allarmeAttivo = false;
        double mediaCalcolata = 0.0;
        int conteggioAttuale = 0;

        // SEZIONE CRITICA PROTETTA DAL SEMAFORO
        semaforo.acquire();
        try {
            this.numeroRilevazioni++;
            this.sommaRilevazioni += valore;
            this.mediaCorrente = (double) this.sommaRilevazioni / this.numeroRilevazioni;

            mediaCalcolata = this.mediaCorrente;
            conteggioAttuale = this.numeroRilevazioni;
            allarmeAttivo = (this.mediaCorrente > this.sogliaMassima);
        } finally {
            semaforo.release(); // Sempre rilasciato!
        }

        EsitoAggiornamento esito = new EsitoAggiornamento(valore, conteggioAttuale, mediaCalcolata, sogliaMassima, allarmeAttivo);

        // Notifica ai monitor FUORI dal semaforo per non bloccare altri sensori
        if (allarmeAttivo) {
            inviaNotificaAllarme(esito);
        }
        return esito;
    }
    // ... metodi aggiungiMonitor, rimuoviMonitor, inviaNotificaAllarme ...
}
// GestoreClient: discrimina SENSOR da MONITOR e gestisce il protocollo
public class GestoreClient implements Runnable {
    private final Socket socket;
    private final RegistroInquinamento registro;

    public GestoreClient(Socket socket, RegistroInquinamento registro) {
        this.socket = socket;
        this.registro = registro;
    }

    public void run() {
        try (
            BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()));
            PrintWriter out = new PrintWriter(socket.getOutputStream(), true)
        ) {
            String primaLinea = in.readLine();
            if (primaLinea.startsWith("SENSOR:")) {
                int valore = Integer.parseInt(primaLinea.substring(7).trim());
                RegistroInquinamento.EsitoAggiornamento esito = registro.registraRilevazione(valore);
                out.println("ACK: Ricevuto | Media=" + esito.getMedia() + " | Allarme=" + esito.isAllarme());
                // Connessione sensore chiusa subito al termine del blocco try
            } else if (primaLinea.equalsIgnoreCase("MONITOR")) {
                registro.aggiungiMonitor(out);
                out.println("OK: Monitor registrato");
                // Ciclo bloccante per mantenere aperta la connessione del monitor
                String dummy;
                while ((dummy = in.readLine()) != null) { }
            }
        } catch (Exception e) { ... }
    }
}
// Server Inquinamento: avvia ServerSocket e passa l'istanza condivisa a ciascun gestore
public class ServerInquinamento {
    private final int porta;
    private final double sogliaMassima;
    private final RegistroInquinamento registro;

    public ServerInquinamento(int porta, double sogliaMassima) {
        this.porta = porta;
        this.sogliaMassima = sogliaMassima;
        this.registro = new RegistroInquinamento(sogliaMassima);
    }

    public void avvia() {
        try (ServerSocket serverSocket = new ServerSocket(porta)) {
            while (true) {
                Socket clientSocket = serverSocket.accept();
                new Thread(new GestoreClient(clientSocket, this.registro)).start();
            }
        } catch (IOException e) { ... }
    }

    public static void main(String[] args) {
        // Unico metodo static ammesso dalla JVM. Richiede soglia ed avvia l'oggetto Server
        double soglia = ...; // input da tastiera [80, 100]
        new ServerInquinamento(8080, soglia).avvia();
    }
}
// Client Sensore: loop infinito con generazione [80, 100], invio e sleep 5s
public class ClientSensore {
    private final String host;
    private final int porta;
    private final Random random = new Random();

    public void esegui() {
        while (true) {
            int valore = 80 + random.nextInt(21); // [80..100]
            try (
                Socket socket = new Socket(host, porta);
                PrintWriter out = new PrintWriter(socket.getOutputStream(), true);
                BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()))
            ) {
                out.println("SENSOR:" + valore);
                String ack = in.readLine();
                System.out.println("Ricevuto dal server: " + ack);
            } catch (IOException e) { ... }

            Thread.sleep(5000); // 5 secondi di sospensione prima del nuovo ciclo
        }
    }
}
// Client Monitor: apre la socket, invia "MONITOR" e resta in ascolto passivo
public class ClientMonitor {
    public void avvia() {
        try (
            Socket socket = new Socket(host, porta);
            PrintWriter out = new PrintWriter(socket.getOutputStream(), true);
            BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()))
        ) {
            out.println("MONITOR");
            String messaggio;
            while ((messaggio = in.readLine()) != null) {
                if (messaggio.startsWith("ALLARME:")) {
                    System.out.println("🚨🚨🚨 ATTENZIONE: " + messaggio);
                }
            }
        } catch (IOException e) { ... }
    }
}
🔄 Il Ciclo di Vita della Registrazione Dinamica
  1. 1. Handshake Iniziale: Il client apre socket su porta 8080 e invia "MONITOR\n". Il server riconosce il ruolo persistente.
  2. 2. Iscrizione Thread-Safe: Lo stream PrintWriter out viene memorizzato in registro.aggiungiMonitor(out).
  3. 3. Risposta di Benvenuto: Il server comunica la soglia attiva: "OK: Registrazione monitor completata. Soglia: 88.0".
  4. 4. Connessione Persistente (Long-Lived): Il thread del server rimane bloccato su in.readLine() in attesa passiva (stato WAITING a zero consumo CPU).
  5. 5. Notifica Push Asincrona: All'allarme, il server itera sulla lista e invia il messaggio formattato a tutti i monitor connessi.
  6. 6. Deregistrazione Automatica: Se il monitor cade o si chiude, il blocco finally esegue registro.rimuoviMonitor(out).
🛡️ Perché CopyOnWriteArrayList invece di ArrayList?

In un server multithread, iterare su una normale ArrayList mentre un altro thread aggiunge o scollega un monitor provoca ConcurrentModificationException.
La CopyOnWriteArrayList garantisce che le notifiche broadcast iterino su uno snapshot immutabile lock-free senza mai andare in crash e senza bloccare le registrazioni.

⚡ Notifiche Broadcast Rigorosamente FUORI dal Semaforo

Il semaforo tutela solo l'aggiornamento dei contatori ($N$, somma, media) e viene subito rilasciato con semaforo.release().
La trasmissione di rete avviene dopo: se avvenisse dentro il semaforo, un monitor lento (slow consumer) o disconnesso bloccherebbe la sezione critica, paralizzando tutti i sensori della città!

// Stralcio RegistroInquinamento.java:
public void inviaNotificaAllarme(Esito esito) {
  for (PrintWriter out : monitorConnessi) {
    try { out.println(msg); out.flush(); }
    catch (Exception e) { monitorConnessi.remove(out); }
  }
}
